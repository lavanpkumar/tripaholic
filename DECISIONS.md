# Decisions

One line per decision or deviation from PLAN.md. Newest blockers first.

## Blockers
- **No `MONGODB_URI` / `GEMINI_API_KEY` in the dev environment yet.** `npm run smoke:mongo` and `npm run smoke:gemini` print "... is not set" and exit with code 1 until they are added to `.env.local`, so the Phase 0 acceptance test still needs a run with real keys. The app itself runs on the local file store meanwhile.
- **Vultr + GoDaddy Registry need the team's accounts.** Planned for Phase 6: deploy files in `deploy/` and a README "Deploy" section; the server, DNS, and HTTPS steps themselves need someone with those accounts.
- **Grok Bot PR access not verified.** Claude Code cannot test Grok Bot. Branches are pushed with a `HANDOFF.md`; whoever opens PRs (Grok Bot or a human with `gh pr create`) should use it.

## Scope
- Sentient OS integration dropped (team decision, 2026-11-14: it is only a sponsor). The booking agent (Phase 4) will be native Gemini function calling behind `runAgent(ctx, request, emit)`.

## Phase 0
- Next.js 16.4 App Router + React 19 + Tailwind v4; Node runtime only.
- shadcn/ui not used: the repo already had a finished visual design (initial commit), so components are small hand-built Tailwind pieces in that design's palette (pine green accent, Inter). Avoids the default-template look.
- MongoDB via the official `mongodb` driver (no Mongoose). Documents use a string UUID as `_id`; the app sees it as `id`.
- Local fallback store: when `MONGODB_URI` is empty, the same repository API reads/writes `.data/db.json`. Lets the app and demo run before Atlas is wired up.
- Planned for Phase 3 (planner) and Phase 4 (agent): an offline fallback for AI. When `GEMINI_API_KEY` is empty or Gemini fails, a deterministic planner and agent produce results and the UI labels them "offline", so the demo never dead-ends on an API failure. Phase 0 only reports whether Gemini is configured.
- Gemini model comes from `GEMINI_MODEL`; `lib/env.ts` has a fallback only so a missing var does not crash the server. Confirm the current fast model at https://ai.google.dev/gemini-api/docs/models when adding the key.
- Event times are floating local ISO strings (`2027-02-08T09:00:00`, no offset) in the destination's wall-clock time. The calendar (Phase 2) will run in UTC mode so these display unchanged; booked flights (Phase 4) will be converted from origin to destination time.
- Trip status is derived using "today" in the destination's time zone.
- Dynamic server pages call `await connection()` (Next 16 guidance) instead of `export const dynamic`.
- `AGENTS.md` is generated by `next dev`; committed as the file itself recommends.
- Single demo user (`demo-user`), no auth, per PLAN.md Section 3.
- Gemini errors are typed (`GeminiError.kind`: auth, rate_limit, timeout, server, grounding_unsupported, bad_request, invalid_output). 429/5xx get bounded backoff (2 retries, 1 s then 2 s); auth, timeouts, and other 400s are thrown at once. Search grounding is dropped only when Gemini says the tool is unsupported for the request, and that fallback is logged. (PR #1 review.)
- The file store sorts like Mongo (numbers numerically, before strings) so local and Atlas ordering agree. (PR #1 review.)
